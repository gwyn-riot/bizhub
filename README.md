# BizHub

**Единая финансовая панель для предпринимателя.** Счета, платежи, поступления, сроки и прогноз денежного потока в одном интерфейсе, с предупреждением о кассовых разрывах заранее.

Проект выполнен в рамках соревнования от ВТБ, тема «Финтех без границ: банк будущего для клиентов и бизнеса». Статус: **MVP**.

## Проблема

Владелец малого бизнеса живёт в нескольких системах: банк, учёт, налоговая, маркетплейсы. Из-за этого возникают кассовые разрывы, пропущенные платежи и штрафы. BizHub собирает всё в одном месте и отвечает на вопрос: «хватит ли денег и что нужно сделать сегодня».

## Возможности

- **Дашборд:** остаток, ожидаемые поступления, предстоящие платежи, прогноз остатка через 30 дней.
- **Прогноз кассового разрыва:** график остатка на 30 дней и предупреждение с датой и суммой минимума. Просроченные операции учитываются в день 0.
- **Календарь платежей и поступлений:** добавление, удаление, кнопки «Оплатить» и «Получено». При подтверждении остаток пересчитывается.
- **Импорт банковской выписки (CSV):**
  - предпросмотр перед записью;
  - автоопределение разделителя, кодировки (UTF-8 и windows-1251), колонок, форматов дат и сумм;
  - сопоставление фактических операций с плановыми;
  - защита от дублей при повторной загрузке;
  - автокатегоризация по назначению платежа.
- **Авторизация:** регистрация и вход по email и паролю (JWT), данные каждого пользователя изолированы. При регистрации можно загрузить демо-данные.

## Быстрый старт

Требуется Node.js 18 или новее.

```bash
npm run install:all     # зависимости сервера и клиента
npm run dev:server      # API на http://localhost:3001
npm run dev:client      # интерфейс на http://localhost:5173
```

Откройте http://localhost:5173, нажмите «Создать аккаунт», оставьте галочку «Загрузить демо-данные».

### Переменные окружения сервера

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `PORT` | `3001` | порт API |
| `JWT_SECRET` | `dev-secret-change-me` | секрет подписи токенов, **обязательно задать в продакшене** |
| `DB_FILE` | `bizhub.db` | путь к файлу SQLite |

## Импорт выписки

Кнопка «Импорт выписки (CSV)» на дашборде.

**Формат файла**
- Кодировка UTF-8 или windows-1251, разделитель `;`, `,` или табуляция.
- Обязательны колонки «Дата» и «Сумма» (одна колонка со знаком) либо «Дебет» и «Кредит».
- Колонки «Назначение платежа» и «Контрагент» необязательны, но используются для названия и категории.
- Даты: `дд.мм.гггг` или `гггг-мм-дд`. Суммы: `−1 234,56 ₽`, `1234.56`. Строки с итогами и текст перед заголовком пропускаются.

**Логика**
1. Загружаете файл и смотрите предпросмотр: каждая строка помечена как *новая*, *сопоставлена с планом* или *дубликат*.
2. Операции из выписки считаются фактическими. Если в календаре есть плановая операция с той же суммой (±1%) в пределах ±5 дней, она закрывается. Иначе создаётся новая выполненная операция.
3. Чекбокс «Учесть операции в остатке» определяет, изменится ли баланс.
4. Повторная загрузка того же файла дублей не создаёт.

Пример файла: `sample-statement.csv`.

## API

Все запросы, кроме авторизации, требуют заголовок `Authorization: Bearer <token>`.

| Метод | Путь | Описание |
|---|---|---|
| POST | `/api/auth/register` | регистрация `{ email, password, demo }` |
| POST | `/api/auth/login` | вход `{ email, password }` |
| GET | `/api/state` | остаток, операции, прогноз на 30 дней |
| POST | `/api/events` | добавить операцию `{ title, amount, due, category }` |
| POST | `/api/events/:id/done` | отметить выполненной, обновить остаток |
| DELETE | `/api/events/:id` | удалить операцию |
| POST | `/api/import` | импорт выписки `{ csv, dryRun, applyBalance }` |

Сумма платежа отрицательная, поступления положительная. Дата в формате `YYYY-MM-DD`.

## Тесты

```bash
cd server && node test.js
```

Покрывают разбор CSV (разделители, кавычки, дебет/кредит, служебные строки), форматы дат и сумм, категоризацию.

## Сборка для продакшена

```bash
npm --prefix client run build   # статика в client/dist
NODE_ENV=production JWT_SECRET=<секрет> node server/index.js
```

Сервер отдаёт только API, поэтому `client/dist` нужно раздавать отдельно (например, через nginx с проксированием `/api` на сервер).

## Ограничения MVP

- Нет интеграции с банковским API, данные загружаются вручную или из CSV.
- Один счёт на пользователя, нет ролей и повторяющихся платежей.
- Валидация входных данных минимальная, нет ограничения частоты запросов.
- Автокатегоризация работает по простым ключевым словам.
- Расчёт налогов не реализован.

## План развития

1. Календарь налогов и расчёт авансовых платежей по системе налогообложения клиента.
2. Повторяющиеся платежи, прогноз поступлений по истории контрагентов.
3. Подсказки и рекомендации банковских продуктов (например, овердрафт при риске разрыва).
4. Подключение выписок через API банка вместо CSV.
5. Пилот с предпринимателями, сбор метрик: активные пользователи в неделю, доля вовремя оплаченных обязательств, конверсия в продукты.
